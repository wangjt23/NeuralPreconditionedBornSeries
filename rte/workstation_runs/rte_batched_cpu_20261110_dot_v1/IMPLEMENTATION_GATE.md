# Batched angular inverse CPU bridge

## State and invariant ledger
Original A is the stored periodic N128, L12, g0.65 RTE. The background inverse is restricted to the same 17 tangential modes, and inner P8 A P8 remains original-operator FGMRES with tolerance 1e-4 and maximum 8 iterations. The accepted decision control remains paid compact4. Sealed E's sequential angular inverse is the attribution control. Its angular band is approximate; original-G residual correction remains target 1e-10 with at most 3 corrections per mode and column. Outer original residual, evaluated relative-error bound and relative-field-difference gates remain 1e-5, 1e-3 and 1e-4. Sources stay [0,4,7,14], amplitude stays 3. No GPU, conjugate-mode reuse, phase truncation or new samples.

## Debate round one
Directly porting the sequential Python loops would cheaply test a weak GPU execution form but leave 17-fold dispatch overhead. Batched mode execution changes representation while preserving independent systems; its risk is a tensor-layout or correction-mask error. Keeping the already successful CPU method avoids that risk but does not test GPU portability. Choose the batched representation and its cheapest decisive CPU equivalence bridge before any GPU use. CPU speed is reported, not required to improve to establish execution equivalence.

## Debate round two
Mode batching must not pool residual norms: small and tiny nonzero columns need independent relative tests. Exactly zero columns receive exactly zero solution/residual, with no absolute floor applied to nonzero columns. The periodic corner remains a rank-256 update for each of 17 independent systems. Keep all positive and negative modes explicitly because no stored-Nyquist conjugacy theorem has been proved. Independent original-A0 embedding and the sealed sequential inverse are stronger controls than checking the batched band alone.

Before the full bridge, qualify all 17 original-G actions, original-A0 actions, repaired inverses and sequential inverse differences. Use E's fixed one-column vectors; action difference target 1e-12, repaired inverse difference target 1e-10, original-G/A0 inverse residual target 1e-10. Then test all-zero, mixed zero/nonzero/1e-200 columns, and mixed inactive/active modes. A failure ends numerical work without changing thresholds. Only after all qualify, run one fresh paid four-RHS batched CPU candidate plus ordinary accepted reference solves. Compare its call pattern and acceptance with sealed E, not as a new matched performance claim.

## Resource and stopping limits
CPU0, one thread, CUDA disabled. Each numerical stage has a 180-second alarm; accumulated numerical-stage wall time is limited to 600 seconds. Qualified and full stages run separately and save partial failure receipts. Complete full-stage admission is coordinated with Schur. Process peak RSS is measured and labeled as process-wide, including imports and controls, not isolated factor memory. Factor assembly, chain LU/update, corner construction, validation, applications, checks and first-RHS cost are recorded. E and earlier evidence remain unchanged. Stop any failed qualification, timeout or original-acceptance failure, retaining partial data.
