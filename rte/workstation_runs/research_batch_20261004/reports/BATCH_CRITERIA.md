## Invariants for A and B

The target is the exact nominal original discrete H with captured, actually assembled, pure-imaginary D64 and exact stored t/s/phase/weights/source/candidate bits. Mathematical spatial DFT roots are independently enclosed. No regenerated ideal geometry, altered Nyquist convention, low-D32 substitution, rounded phase-times-weight matrix or relaxed CPU mode is permitted.

For each point-center FFT layer, an outward local error norm e and the incoming global Euclidean radius E give `E_next >= sqrt(2)*E + e`. Apply the factor once per complete layer across all lines/angles; retain the incoming radius even when a point center is zero. Normalize both inverse axes by their exact reciprocals, enclosing center scaling. The stored D64 multiplier propagates uncertainty by its exact maximum absolute imaginary coefficient. Collision and final subtraction contribute their own local norm errors. No ordinary norm plus one final `nextafter` supplies an enclosure of all preceding reductions.

Use tau=1/100000, alpha=1/100, and outward point-center norm C_U, radius E_U and source lower norm Q_L. Acceptance requires C_U <= .99*tau*Q_L, E_U <= .01*tau*Q_L, and C_U+E_U <= tau*Q_L. The exact stored-coefficient coercivity margin m gives the solution test R_U/(m*X_L-R_U) <= 1/1000 with a positive denominator. The separate paired test is directly `||x-b||_U <= (1/10000)*||b||_L`. Two individual 1e-3 solution bounds do not establish that paired test. An absent baseline is not paired admission.

Keep the existing correctly rounded binary64/adjacent-value endpoint contract, non-fast-math/non-contraction native build, finite checks, nearest-rounding and no-FTZ/no-DAZ guard. The read-only register guard is a contract check, not an empirical arithmetic probe or proof of the compiler. These input-specific CPU certificates require no GPU-wide error bound and establish none.

## Cheap cost changes in ranked order

1. **Upper-only local defect norms, already isolated as B.** A local box-to-center defect needs only an upper norm. Source, candidate and paired-baseline lower norms remain necessary. Keep the same positive upper-square/add/tree/sqrt operations so numerical equivalence can be tested without a new global error theorem.
2. **Execute singleton/cardinal shortcuts before generic arithmetic.** The current draft `_rmul` and `_radd` first compute generic interval arithmetic and then mask exact zero/one/sign cases. They reduce width but do not skip most endpoint work. Partition exact singleton 0, +/-1 and cardinal roots first; use bit-copy/sign/swap operations only there and invoke native arithmetic only on the complement. This is a small separate implementation direction if A/B show those categories matter. A cardinal product may be exact while its surrounding butterfly addition is not. Underflow is never replaced by a small-value threshold.
3. **Reuse immutable coefficient-only work and storage.** Exact hash keys may cover certified roots, bit-reversal/index tables, D64 maximum, exact Fraction coefficient margin, interval phase-weight products and fixed work buffers. Keys include all operand bytes, dtype/shape/angular ordering, grid/index convention and proof/code version. An interval enclosure or exact rational product may be cached; a separately rounded point product cannot silently replace the original collision target. Setup, memory, hash validation and cache invalidation are charged. Do not reuse field-dependent defects, norms, centers, radii or a prior acceptance result by material hash.
4. **Fuse the point-stage and positive error reduction at the existing native boundary.** This can remove Python/ctypes calls, broadcast copies, temporary rectangles and allocator traffic. It preserves the same proof if it saves both old butterfly inputs, encloses each primitive, measures the actual stored next center, and uses an outward whole-stage sum. An ordinary compiler/vector dot or an unchecked fused endpoint expression is not a substitute. This is contingent engineering, not part of the current three-job batch or permission for a proof campaign.

The first two changes can lower arithmetic/allocation work without changing the target or gates. The third removes repeated fixed-operand preparation, but cannot make cold setup free. The fourth has larger implementation risk and should follow measured bottlenecks. Per-stage native/recenter/norm timers are nested diagnostics; only complete external wall time decides complete verification cost. Compare ordinary solver economics separately until both baseline and candidate receive the same fresh checker, direct paired test and all setup costs.
