## Debate round one: three non-isomorphic concepts

### C1. Scope and regime qualification

Change the evidence domain, not the solver. Keep E unchanged and predeclare either a scale-transfer case on existing N256 development parents or a genuinely new, independently specified coefficient geometry. The question is whether the layered reference remains a useful preconditioner when the original projected coupling changes.

Positive prediction: the angular representation still follows the original stored ordinate/phase structure, independent of how the normal profile varies. Adverse prediction: a strongly two-dimensional coefficient field defeats the chosen one-dimensional background; inner8 then fails even if each G_k solve is accurate. Increasing normal size also increases the Ny-by-Ny block cost. New material coverage and a new scale are distinct hypotheses and should not be mixed in the first test.

Attribution control: unchanged E inverse, original-G/A0 qualification, same physical instance and ordinary reference. Decision control: fresh compact4 plus the strongest previously qualified classical solver for the declared new family, not an assumed compact4 winner everywhere. Cheapest test after a separate protocol would be one unscreened instance and its full four-source cost, stopping on failure. Scientific value is scope, not a new algorithm. Defer now because an avoidable representation cost can be resolved on the existing instance without consuming new evidence.

### C2. Eliminate the redundant physical tangent grid inside P8

Change the inner state space and exact projected operator. Keep vectors as [1,12,128,17] tangent-Fourier coefficients throughout inner FGMRES instead of [1,12,128,128] fields. Represent multiplication by each actual stored coefficient using a17-by17 Toeplitz matrix per normal position. Only difference frequencies -16,...,16 contribute to the projected product, even if the original material has all128 Fourier components. Apply the existing E blocks directly to these17 coefficients.

This changes which calculation is performed, not merely Python dispatch. It removes repeated full tangent FFT/projection/lifting, reduces Krylov vector work, and computes the original projected coefficient coupling without material low-rank fitting. The governing identity and exact normalization are in the locked plan. Full-A acceptance remains outside the compressed inner representation.

Positive prediction: saved inner state and FFT/orthogonalization work shrink materially while the E mode inverses and original call pattern persist. Adverse prediction:17-by17 coefficient contractions and unchanged mode inverse repairs dominate, so added coefficient setup and original-A validation erase the savings. Finite-precision changes could also cross an inner stopping boundary; H's third inner residual was only1.70% below its unchanged threshold. Attribution control is the existing full-grid projection/restore E implementation, not a dense oracle. Decision control remains compact4. Select this concept for one bounded CPU bridge and cost gate.

### C3. Resource-constrained deployment, rather than an algorithmic speed claim

Change the scheduling decision, not A or the number of sources. When a compatible GPU is actually free and device-warm, G's measured compact4 cost is .461313 seconds for the complete fixed four-source batch and .246436 seconds for the first source. E's three CPU confirmation observed walls are15.55-16.11 seconds. These are different devices and timing campaigns, not an isolated algorithmic speedup ratio. They nevertheless prevent presenting the CPU gain as the best observed latency when a free warm A6000 is available.

During an actual long GB GPU reservation, the CPU path can finish without preemption. The operational decision would compare T_CPU with the observed GPU waiting time plus T_GPU, using a verified queue state and the same cold/warm convention. No hypothetical long queue, extra sources, repeated factor reuse or future production workload is assumed. G separately paid .284251 seconds of context creation and51.228095 seconds of neutral library warm-up, so its device-warm figure cannot be silently called process-cold latency.

The cheapest decisive step is this existing-receipt/state audit, not another GPU experiment. Current evidence supports a conditional CPU fallback use case and a GPU compact4 preference when a compatible GPU is free and warm. It does not support building a scheduling service or claiming a memory-limited new capability. In particular, compact4 uses O(N_t N_n L^2 log N_n) PCR storage, not an assumed cubic dense scaling; its actual source does not justify a fabricated memory-exhaustion advantage for E. Keep G closed.

## Debate round two: cost ceiling, nulls and selection

The bottleneck has moved, but not entirely into the inner solve. Saved E confirmation receipts charge4.12-4.22 seconds for all inner solves, against15.55-16.11 seconds of observed complete batch wall. H charges5.22-5.27 seconds inside19.47-19.59 seconds. If only the inner work changed and were made literally free, the saved E batch would still require11.44-11.89 seconds, and H14.20-14.37 seconds. These are conditional arithmetic ceilings, not timing predictions or lower bounds for unrelated algorithms. They show why C2 may yield a useful CPU improvement but cannot by itself explain away the observed warm-GPU latency gap.

The strongest null is that full-grid embedding is cheap relative to E's unchanged block solves and outer TSA64. C2 must therefore beat the existing E complete paid wall, not only show a smaller state, faster isolated FFT or preserved iteration count. A second null is that changing coordinates merely alters floating-point stopping. The frozen action/inverse bridges, original projected residual and exact call-pattern checks address that attribution risk. A failed bridge stops this representation rather than triggering tolerance or source retuning.

Choose C2 because it has an exact finite-projection identity, no need for new samples and a bounded empirical uncertainty. It is new relative to the stopped POD, dense-GPU and eager-batched-GPU paths: their premises retained full-grid inner vectors or changed inverse setup/execution, whereas this removes the unused tangent coordinates and material multiplication work. Its closest classical category is Fourier-Galerkin representation and projected Krylov solution. No novelty priority is claimed.

The first authorized numerical step, if the coordinator accepts the plan, should be the all17-mode/action/inverse bridge on CPU0, followed conditionally by a single fresh compact4/E/compressed comparison. Only a complete first-pass win allows one reversed triplet. C1 is deferred, C3 is resolved as a scope statement rather than a new run. No GPU, N256 or reserved-data action is included.
